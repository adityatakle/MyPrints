# MyPrints — Automated Edge-Cloud Printing & Micro-Fulfillment Platform

**MyPrints** is an automated, zero-touch print fulfillment platform engineered to digitize hyper-local micro-retail print shop operations. It replaces manual, privacy-risky over-the-counter workflows—such as sharing files over WhatsApp, forwarding emails, or using physical USB drives—with a self-serve web application and an autonomous edge execution daemon.

---

## 💡 Executive Summary for Technical Evaluators

When evaluating this project from an engineering perspective, the key takeaway is **resource efficiency and architecture design**:

* **Client-Offloaded Computing:** By executing CPU-heavy PDF parsing and slicing in the browser via WebAssembly (`pdf-lib`), backend server CPU/RAM usage is reduced to near zero.
* **Direct-to-Cloud Ingestion:** Files stream directly from client RAM to AWS S3 via presigned URLs, bypassing application servers to eliminate cloud bandwidth bottlenecks.
* **Edge-Cloud Hardware Automation:** A Python daemon on local print shop PCs polls the cloud control plane, dynamically overlays in-memory OTP cover pages, and interfaces with native Windows printer spoolers (`win32print`) for completely hands-free execution.

## 🔑 Key Engineering Challenges & Solutions

### 1. Eliminating Web Server Bandwidth & CPU Overhead

* **Problem:** Traditional file upload platforms upload raw files to the backend server, which slices pages server-side. Processing multi-hundred-megabyte PDFs crashes low-tier server instances and creates heavy bandwidth costs.
* **Solution:** Offloaded PDF manipulation entirely to the client browser using `pdf-lib` (WebAssembly). The client extracts the requested page range in browser RAM and streams the processed binary payload directly to AWS S3 using presigned `PUT` URLs generated by Django. Backend load remains near zero regardless of file size or user concurrency.

### 2. Native Windows Printer Spooling & Zero-Touch Execution

* **Problem:** Print shop operators manually open files, navigate Windows print dialogs, select duplex settings, and manage paper trays for every customer order.
* **Solution:** Engineered a headless Python daemon (`base_script.py`) that polls the cloud control plane out-of-band over HTTPS. The script uses low-level Windows APIs (`win32print`, `win32con`) to auto-query local printer capabilities (`DC_DUPLEX`, `DC_COLORDEVICE`), stamps a 4-digit pickup OTP cover page onto the document in memory (`reportlab` + `pypdf`), and silently drives SumatraPDF CLI spooling without user prompts.

### 3. State Integrity & Page Resubmission Guards

* **Problem:** Accidental page reloads or form resubmissions in client carts caused duplicate DB entries, stale state lookups, and unhandled 500 exceptions on invalid cart parameters.
* **Solution:** Implemented strict Post/Redirect/Get (PRG) patterns backed by Django session flash messages. Refactored anonymous client handling to transition legacy browser identities (`localStorage` UUIDs) into secure, server-managed session cookies (`request.session['user_id']`) while adding defensive ORM validation prior to database lookup calls.

### 4. Privacy-First Ephemeral Document Lifecycle

* **Problem:** Personal documents (Aadhaar cards, transcripts, legal contracts) left on print shop computers or web servers pose major data privacy hazards.
* **Solution:** Established an ephemeral storage lifecycle. Uploaded PDFs in AWS S3 and local edge downloads carry an automated 24-hour retention deletion window, guaranteeing that customer documents are completely purged after fulfillment.
